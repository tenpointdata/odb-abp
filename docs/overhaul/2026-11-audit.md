# odb-abp: capability and circumstance audit, phase 1 improvements

Date: 2026-11-02. Scope: `tenpointdata/odb-abp` (fork of `orientechnologies/orientdb`), branch `develop`
at `a13262f` (4.0.0-SNAPSHOT, Java release 17). Phase 1 changes are on branch `ops/overhaul-phase1`.

## Summary

- The codebase is a large, working multi-model database (476k lines of main Java, 249k of tests,
  22 Maven modules) maintained upstream almost entirely by one person (77% of the 2,366 commits since
  2024; dependabot most of the rest).
- Its operational state is weaker than its feature set. The audit found **eight capabilities that are
  currently broken or degraded** on `develop`, most of them recent regressions that fail silently: the
  Docker images can't start the server, the ETL server plugin and Kerberos authentication can't load,
  native OS access silently falls back (512 open files on every Linux host), container memory is
  misdetected on cgroup v2, a remote shutdown leaves every database needing WAL recovery, a failed
  backup reports success, and `dserver.sh` is missing from the distribution.
- Upstream CI passes on the first attempt only **56%** of the time (flaky tests cause 62% of failing
  runs), and its wall-clock nearly doubled in October (about 22 to 41 minutes per job).
- Phase 1 fixes all eight, plus build, packaging and CI improvements, in 10 focused commits. Nothing is
  removed. Every fix has a test or an end-to-end check in a real container (before/after below).

## 2. Circumstance

### Project and upstream

- Fork created 2026-11-02, public, GitHub Actions enabled, no secrets configured.
- Upstream is active: monthly 3.2.x releases (3.2.57 on 2026-10-05), 378 open issues (distributed
  mode, memory use in Docker and missing metrics are recurring themes), an in-progress refactoring of
  component loading to Java service loaders (October 2026), and WIP branches for Java 21, Hazelcast
  upgrade and distributed refactors.
- Bus factor: one maintainer. The fork should expect to carry fixes and to upstream them selectively.

### Packaging and runtime operations

| Finding | Evidence |
|---|---|
| Docker images based on Java 8: the 4.0 server can't start; run as root, no health check, tarball kept in a layer | `packages/*/docker/Dockerfile` |
| Native POSIX access silently disabled since 2024-10 (ASM excluded from `jnr-posix`): open files limit 512 instead of `RLIMIT_NOFILE/2`, address-space limit ignored | probe in container: `NoClassDefFoundError: org/objectweb/asm/ClassVisitor` |
| cgroup v2 not supported: containers treated as hosts (2 GB left to the OS instead of 256 MB) | container logs, before/after below |
| Percentage `memory.leftToOS`/`leftToContainer` truncated to an int (capped at 2 GB) | `OMemoryAndLocalPaginatedEnginesInitializer` |
| Remote shutdown (`shutdown.sh -u/-p`) interrupts its own WAL flush; storages need recovery on next start; process always exits 1 | reproduced with a persistent volume |
| `backup.sh` exits 0 after a failed backup | `server/script/backup.sh` |
| `dserver.sh`/`.bat` missing from the distribution since the move to `packages/community` | assembly descriptor |
| Fixed 2 GB heap in `server.sh`: in a 1 GB container heap + cache = 2.2 GB, OrientDB itself warns of out-of-memory | container logs |
| Low-disk protection is dead code (never called; default threshold negative); WAL unbounded by default | `OWOWCache.checkLowDiskSpace`, `OGlobalConfiguration` |
| Observability: only `GET /ping` (liveness), no readiness; metrics/Prometheus only in the unpackaged agent; disk cache (largest memory consumer, off-heap via `Unsafe`) invisible, its MXBean never registered; plain-text JUL logs | server and agent sources |
| First start without a TTY and without `ORIENTDB_ROOT_PASSWORD` fails: the prompt promises "BLANK=auto generate" but a null password is used | `OServer` root user creation |
| Security defaults: listeners on 0.0.0.0 without TLS; Hazelcast multicast join with default group and `autoDeploy`; Hazelcast 3.12 is end-of-life | config files |

### Code health and forward compatibility

- `sun.misc.Unsafe` memory access (off-heap disk cache allocator, comparators, binary converter) is on
  the JDK removal path (JEP 471/498): warnings from JDK 24, denied by default in a future release.
  Comparators and converters have safe fallbacks; the direct memory allocator doesn't.
- Hazelcast 3.12 (EOL) underpins distributed mode, the area with most open upstream issues.
- Studio is AngularJS 1.8 + Angular 4 + webpack 3, 93 npm dependencies.
- 1,433 non-script files (mostly Java sources) carry the executable bit.

Compatibility notes:
- Docker: the image now runs as uid 2424. Bind-mounted directories created by a root container need
  `chown -R 2424:2424`. A fixed heap is still available with `ORIENTDB_OPTS_MEMORY`.
- Containers on cgroup v2 now get a larger disk cache by default (the documented
  `memory.leftToContainer` behaviour). Set `storage.diskCache.bufferSize` to pin it.
- CI: JDK 24 dropped from the matrix (end of life, superseded by 25); the test re-run applies in CI only.

## 5. Roadmap

Ordered by operational value. Items marked **decision** need an owner's call before work starts.

1. **Investigate the distributed sync stall** behind the October CI slowdown (`SyncOpsTest`, since
   ~2026-10-15): a 290 s blocked read during full sync is likely a real defect for nodes joining a
   cluster, not only a slow test.
2. **Fix the top flaky tests** (`OCoordinatedDistributedOpsPingTimeoutTest`: injectable clock;
   `OMatchStatementExecutionTest`/`OCommandExecutorSQLSelectTest` setup), and the `tests` module
   slowdown (2-4 min silent gap after `demo_objectschema`). Then the CI re-run can be removed.
3. **Decision: first start without a password.** Either generate a root password and print it once
   (what the prompt promises; it ends up in container logs) or fail fast with a clear message.
   Also accept `ORIENTDB_ROOT_PASSWORD_FILE` for Docker/Kubernetes secrets.
4. **Readiness and metrics:** an unauthenticated readiness endpoint (storages open, WAL recovery done,
   distributed node online); register the direct memory MXBean; **decision:** package the agent's
   Prometheus metrics in the community distribution or build a minimal exporter.
5. **Low-disk protection:** wire `checkLowDiskSpace` with a positive default threshold and switch
   storages to read-only before the disk fills (behaviour change: configurable, off by default first).
6. **Decision: Studio source.** Build Studio from this repository in the default build (needs
   Node/Yarn in CI) or pin a released Studio artifact, instead of whatever upstream published last.
7. **Script hardening:** `shutdown.sh` (stale PID, no timeout), `server.sh` PID handling, passwords on
   the command line, `orientdb.service` (invalid `ExecStart`, missing `SuccessExitStatus=143`,
   `LimitNOFILE`), `oetl.sh` overriding `JAVA_OPTS`; `-XX:HeapDumpPath`/GC logging in `server.sh`.
8. **Forward compatibility:** add `--sun-misc-unsafe-memory-access=allow` for JDK 23+ in the scripts
   now; plan the move of the direct memory allocator to the FFM API (Java 22+), keeping Unsafe on 17-21.
9. **Distributed security defaults (decision):** TCP/IP members instead of multicast for new installs,
   TLS keystore generation script, bind address variable.
10. **Hazelcast 3.12 → 5.x** (large, coordinate with upstream's `WIP_upgrade_hazelcast`).
11. Hygiene: remove executable bits from sources, dead `jna.version` property and `animalsniffer`
    profile (Java 1.6 signature), orphaned `lucene/config`, `Class-Path: orient-database-enterprise.jar`
    manifest entries.
